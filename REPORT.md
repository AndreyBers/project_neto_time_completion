# Отчет исследования временного ряда

## 1. Постановка задачи

Цель исследования - построить и сравнить несколько подходов к прогнозированию временного ряда.

В качестве основного ряда выбран `international-airline-passengers.csv` - месячный временной ряд с количеством международных авиапассажиров. Ряд удобен для исследования, так как содержит выраженный тренд, годовую сезонность и меняющуюся амплитуду колебаний.

Постановка задачи:

- тип задачи - одномерное прогнозирование временного ряда;
- режим прогноза - offline forecast;
- горизонт прогноза - последние 12 месяцев ряда;
- разбиение данных - строго по времени;
- перемешивание данных - не используется;
- метрики качества - MAE, RMSE, MAPE, sMAPE.

## 2. Описание данных

В проекте используются временные ряды из папки `data/raw`.

| Ряд | Описание | Частота |
|---|---|---:|
| `daily-total-female-births-in-cal` | рождения девочек в Калифорнии | дневная |
| `international-airline-passengers` | международные авиапассажиры | месячная |
| `mean-monthly-air-temperature-deg` | средняя месячная температура | месячная |
| `monthly-boston-armed-robberies-j` | вооруженные ограбления в Бостоне | месячная |
| `monthly-sales-of-company-x-jan-6` | месячные продажи компании | месячная |
| `weekly-closings-of-the-dowjones` | недельные закрытия Dow Jones | недельная |

Основной ряд для финального сравнения моделей - `international-airline-passengers.csv`.

## 3. EDA и подготовка данных

EDA выполняется в ноутбуке `notebook/01_eda_preprocessing_report.ipynb`.

В ходе анализа проверяются:

- типы данных;
- пропуски;
- корректность временного индекса;
- частота наблюдений;
- наличие тренда;
- наличие сезонности;
- стационарность;
- визуальная структура ряда.

Для проверки стационарности используются тесты ADF и KPSS.

Критерии интерпретации:

- ADF p-value < 0.05 - аргумент в пользу стационарности;
- KPSS p-value > 0.05 - нет оснований отвергать стационарность.

По результатам EDA основной ряд авиапассажиров нельзя рассматривать как простой стационарный ряд: в нем есть восходящий тренд, выраженная годовая сезонность и рост амплитуды сезонных колебаний. Поэтому для прогноза нужны модели, которые умеют учитывать сезонность, тренд или лаговую структуру данных.

## 4. Анализ аномалий

Аномалии анализируются в ноутбуке `notebook/05_anomaly_detection.ipynb`.

Используются 3 метода:

| Метод | Идея метода | Почему выбран |
|---|---|---|
| Rolling z-score | сравнение значения с локальным средним и стандартным отклонением | простой интерпретируемый baseline |
| STL residual anomalies | поиск выбросов в остатках после выделения тренда и сезонности | учитывает сезонную структуру ряда |
| IsolationForest | ML-метод для поиска нетипичных наблюдений по лаговым признакам | позволяет учитывать несколько признаков одновременно |

Анализ аномалий используется как дополнительная проверка качества данных и структуры ряда. Для итогового прогнозирования это важно, потому что сильные выбросы могут искажать оценку тренда, сезонности и метрик качества.

Итоговая таблица сохраняется в `reports/anomaly_detection_summary.csv`.

## 5. Выбор методов прогнозирования

В проекте проверяются несколько групп моделей: baseline, статистические модели, ML-модели и DL-модели.

| Группа | Модель | Фреймворк | Назначение | Обоснование выбора |
|---|---|---|---|---|
| Baseline | Naive | собственная реализация / statsforecast | простой прогноз последним значением | минимальный уровень сравнения |
| Baseline | SeasonalNaive | statsforecast | сезонный baseline | подходит для рядов с выраженной годовой сезонностью |
| Baseline | Drift | собственная реализация / statsforecast | прогноз с учетом среднего тренда | полезен как простой трендовый benchmark |
| Statistical | AutoARIMA | statsforecast | автоматический подбор ARIMA | классический метод для тренда и автокорреляций |
| Statistical | AutoETS | statsforecast | экспоненциальное сглаживание | учитывает уровень, тренд и сезонность |
| Statistical | AutoTheta | statsforecast | Theta-подход | сильный статистический benchmark |
| Statistical optional | Prophet | prophet | тренд + сезонность | используется опционально из-за возможных сложностей установки |
| ML | LinearRegression | mlforecast | линейная модель на лагах | простой и интерпретируемый ML baseline |
| ML | RandomForestRegressor | mlforecast | нелинейная ансамблевая модель | учитывает нелинейные связи лагов |
| ML | HistGradientBoostingRegressor | mlforecast | бустинг по лаговым признакам | часто дает сильное качество на табличных признаках |
| DL | NBEATS | neuralforecast | нейросетевая модель для прогнозирования | сильный DL baseline для временных рядов |
| DL | NHITS | neuralforecast | иерархическая нейросетевая модель | эффективна на разных горизонтах прогноза |
| DL | LSTM | neuralforecast | рекуррентная модель | подходит для последовательностей и зависимостей во времени |

## 6. Результаты экспериментов

Финальные метрики формируются после запуска ноутбуков и сохраняются в папку `reports/`. Ниже приведено сравнение лучших моделей по группам на одном тестовом горизонте 12 месяцев.

| Группа | Лучшая модель | MAE | RMSE | MAPE | sMAPE | Основной вывод |
|---|---|---:|---:|---:|---:|---|
| Baseline | SeasonalNaive | 47.83 | 50.71 | 9.99% | 10.57% | RMSE ниже `Naive` на 52.27 пункта, или на 50.8% |
| Statistical | AutoARIMA | 18.52 | 23.92 | 4.18% | 4.03% | RMSE ниже `SeasonalNaive` на 26.79 пункта, или на 52.8% |
| ML | LinearRegression | 17.18 | 19.36 | 3.56% | 3.60% | RMSE ниже `AutoARIMA` на 4.56 пункта, или на 19.1% |
| DL | LSTM | 16.03 | 18.01 | 3.37% | 3.37% | RMSE ниже `LinearRegression` на 1.35 пункта, или на 7.0% |

По метрике `RMSE` лучший результат в текущем эксперименте показала `LSTM`: RMSE = 18.01. На втором месте находится `LinearRegression`: RMSE = 19.36. Разница между ними составляет 1.35 пункта RMSE, или 7.0% относительно ошибки `LinearRegression`.

Среди статистических моделей лучшей по RMSE стала `AutoARIMA`: RMSE = 23.92. По сравнению с baseline-моделью `SeasonalNaive` она снизила RMSE с 50.71 до 23.92, то есть на 26.79 пункта, или на 52.8%.

Baseline-модель `SeasonalNaive` уступает лучшей модели `LSTM`: RMSE = 50.71 против 18.01. Разница составляет 32.70 пункта RMSE, то есть ошибка `SeasonalNaive` примерно в 2.8 раза выше. По сравнению с `LinearRegression` ошибка `SeasonalNaive` выше на 31.35 пункта RMSE, или примерно в 2.6 раза.

Важно учитывать, что тестовая выборка состоит из одного года. Поэтому лидерство модели в текущем запуске не следует воспринимать как универсальное правило.

## 7. Интерпретация результатов

Результаты экспериментов согласуются со структурой исходного ряда и подтверждаются метриками качества на тестовом горизонте 12 месяцев:

- `Naive` показала худший результат среди baseline-моделей: RMSE = 102.98, MAE = 76.00, MAPE = 14.25%. Это связано с тем, что модель повторяет последнее значение обучающей выборки и не учитывает ни тренд, ни годовую сезонность.

- `SeasonalNaive` улучшила качество относительно `Naive`: RMSE снизился со 102.98 до 50.71, то есть на 52.27 абсолютных пункта или на 50.8%. MAPE снизился с 14.25% до 9.99%, то есть на 4.26 п.п. Это показывает, что учет годовой сезонности существенно важен для данного ряда.

- `AutoARIMA` стала лучшей статистической моделью: RMSE = 23.92, MAE = 18.52, MAPE = 4.18%. По сравнению с `SeasonalNaive` RMSE снизился с 50.71 до 23.92, то есть на 26.79 пункта или на 52.8%.

- `LinearRegression` на лагах и календарных признаках показала лучший результат среди ML-моделей: RMSE = 19.36, MAE = 17.18, MAPE = 3.56%. По RMSE она улучшила результат `AutoARIMA` на 4.56 пункта или на 19.1%.

- `LSTM` показала лучший результат текущего эксперимента: RMSE = 18.01, MAE = 16.03, MAPE = 3.37%. По сравнению с `LinearRegression` RMSE снизился с 19.36 до 18.01, то есть на 1.35 пункта или на 7.0%. Улучшение есть, но оно небольшое относительно роста вычислительной сложности.

Практический вывод: если выбирать модель только по RMSE на текущем тестовом периоде, лидирует `LSTM` с RMSE = 18.01. Однако преимущество перед `LinearRegression` составляет только 1.35 RMSE, или 7.0%, поэтому для дальнейшего развития более практичным вариантом может быть `LinearRegression`: она почти не уступает по качеству, проще интерпретируется и быстрее воспроизводится. `AutoARIMA` можно оставить как сильный статистический benchmark с RMSE = 23.92.

## 8. Pipeline решения задачи

Pipeline реализован в:

- `src/ts_pipeline.py`;
- `notebook/06_final_pipeline.ipynb`.

Компоненты pipeline:

1. загрузка CSV;
2. автоматическое определение колонки даты и значения;
3. приведение данных к временному ряду;
4. определение частоты и сезонности;
5. train/test split без перемешивания;
6. построение baseline-прогнозов;
7. расчет MAE, RMSE, MAPE, sMAPE;
8. измерение времени выполнения;
9. сохранение результатов в `reports/`.

`06_final_pipeline.ipynb` проверяет воспроизводимый базовый pipeline: загрузку данных, train/test split, baseline-прогнозы, расчет метрик и сохранение результатов. Он используется как контрольный benchmark, а не как финальная лучшая модель по качеству.

Результаты сохраняются в:

- `reports/final_pipeline_results.csv`;
- `reports/pipeline_performance.csv`.

## 9. Итоговый вывод

В проекте выполнен полный цикл анализа временного ряда: EDA, проверка стационарности, анализ аномалий, построение статистических моделей, ML-моделей, DL-моделей и baseline pipeline.

Лучший результат по `RMSE` в текущем эксперименте показала `LSTM`: RMSE = 18.01, MAE = 16.03, MAPE = 3.37%. Однако из-за малого размера ряда, короткого учебного запуска и большей сложности поддержки DL-модель не следует автоматически считать лучшим production-вариантом.

Наиболее практичными кандидатами для дальнейшего развития являются:

- `LinearRegression` - RMSE = 19.36, MAE = 17.18, MAPE = 3.56%. Модель уступила `LSTM` только на 1.35 RMSE, или 7.0%, но проще, быстрее и интерпретируемее.

- `AutoARIMA` - RMSE = 23.92, MAE = 18.52, MAPE = 4.18%. Модель улучшила `SeasonalNaive` по RMSE на 26.79 пункта, или на 52.8%, и может использоваться как статистический benchmark.

- `LSTM` - RMSE = 18.01, MAE = 16.03, MAPE = 3.37%. Это лучший результат текущего запуска, но преимущество перед `LinearRegression` небольшое, поэтому перед финальным выбором нужно проверить устойчивость на rolling backtesting.

Итог: цель проекта достигнута. Были проверены разные классы моделей, получены сравнимые метрики качества, построен базовый pipeline и подготовлен отчет исследования.
