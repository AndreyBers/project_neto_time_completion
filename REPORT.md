# Отчет исследования временного ряда

## 1. Цель работы

Цель проекта - построить и сравнить несколько подходов к прогнозированию временного ряда, а затем собрать воспроизводимый базовый пайплайн для загрузки данных, построения прогноза, расчета метрик и сохранения результатов.

В качестве основного ряда выбран `international-airline-passengers.csv` - месячный ряд с количеством международных авиапассажиров. Он хорошо подходит для учебного сравнения методов, потому что в нем заметны восходящий тренд, годовая сезонность и изменение амплитуды сезонных колебаний.

Постановка задачи:

- тип задачи - одномерное прогнозирование временного ряда
- режим прогноза - offline forecast
- тестовый горизонт - последние 12 месяцев ряда
- разбиение - строго по времени, без перемешивания
- метрики - MAE, RMSE, MAPE и sMAPE

## 2. Данные

В проекте используются временные ряды из `data/raw`.

| Ряд | Описание | Частота |
|---|---|---:|
| `daily-total-female-births-in-cal` | рождения девочек в Калифорнии | дневная |
| `international-airline-passengers` | международные авиапассажиры | месячная |
| `mean-monthly-air-temperature-deg` | средняя месячная температура | месячная |
| `monthly-boston-armed-robberies-j` | вооруженные ограбления в Бостоне | месячная |
| `monthly-sales-of-company-x-jan-6` | месячные продажи компании | месячная |
| `weekly-closings-of-the-dowjones` | недельные закрытия Dow Jones | недельная |

Основной ряд для финального сравнения моделей - `international-airline-passengers.csv`.

## 3. EDA и подготовка данных

Основной анализ выполняется в `notebook/01_eda_preprocessing_report.ipynb`.

Проверяются:

- типы данных
- пропуски
- корректность временного индекса
- частота наблюдений
- тренд
- сезонность
- стационарность
- общая форма временного ряда

Для проверки стационарности используются тесты ADF и KPSS.

Правила интерпретации:

- ADF p-value < 0.05 - аргумент в пользу стационарности
- KPSS p-value > 0.05 - нет оснований отвергать стационарность

Основной ряд авиапассажиров нельзя считать простым стационарным рядом: в нем есть восходящий тренд, выраженная годовая сезонность и растущая амплитуда колебаний. Поэтому для прогноза нужны модели, которые умеют работать с трендом, сезонностью или лаговой структурой.

## 4. Анализ аномалий

Аномалии исследуются в `notebook/05_anomaly_detection.ipynb`.

Используются три метода:

| Метод | Идея | Зачем используется |
|---|---|---|
| Rolling z-score | сравнение точки с локальным средним и стандартным отклонением | простой и интерпретируемый базовый метод |
| STL residual | поиск выбросов в остатках после выделения тренда и сезонности | учитывает сезонную структуру ряда |
| IsolationForest | поиск нетипичных точек по значению, лагам и локальным статистикам | позволяет учитывать несколько признаков одновременно |

Анализ аномалий дополняет исследование качества данных. Сильные выбросы могут влиять на оценку тренда, сезонности и итоговые метрики прогнозирования.

Сводная таблица сохраняется в `reports/anomaly_detection_summary.csv`.

## 5. Модели прогнозирования

В проекте сравниваются четыре группы методов: базовые, статистические, ML и DL.

| Группа | Модель | Библиотека | Роль в сравнении |
|---|---|---|---|
| Baseline | Naive | собственная реализация / statsforecast | минимальная точка отсчета |
| Baseline | SeasonalNaive | statsforecast | сезонная точка отсчета |
| Baseline | Drift | собственная реализация / statsforecast | простой прогноз с линейным трендом |
| Statistical | AutoARIMA | statsforecast | автоматический подбор ARIMA |
| Statistical | AutoETS | statsforecast | модель уровня, тренда и сезонности |
| Statistical | AutoTheta | statsforecast | статистический ориентир Theta |
| Statistical | Prophet | prophet | дополнительный эксперимент с трендом и сезонностью |
| ML | LinearRegression | mlforecast | интерпретируемая модель на лаговых признаках |
| ML | RandomForestRegressor | mlforecast | нелинейная ансамблевая модель |
| ML | HistGradientBoostingRegressor | mlforecast | бустинг по табличным признакам |
| DL | NBEATS | neuralforecast | нейросетевая модель временного ряда |
| DL | NHITS | neuralforecast | нейросетевая модель для разных горизонтов |
| DL | LSTM | neuralforecast | рекуррентная модель последовательностей |

## 6. Результаты экспериментов

После запуска ноутбуков итоговые таблицы сохраняются в `reports`. Ниже приведено сравнение лучших моделей каждой группы на одном тестовом горизонте.

| Группа | Лучшая модель | MAE | RMSE | MAPE | sMAPE | Комментарий |
|---|---|---:|---:|---:|---:|---|
| Baseline | SeasonalNaive | 47.83 | 50.71 | 9.99% | 10.57% | учитывает годовую сезонность и заметно лучше обычного Naive |
| Statistical | AutoARIMA | 18.52 | 23.92 | 4.18% | 4.03% | лучший результат среди статистических моделей по RMSE |
| ML | LinearRegression | 17.18 | 19.36 | 3.56% | 3.60% | хорошо использует лаги и календарные признаки |
| DL | LSTM | 16.03 | 18.01 | 3.37% | 3.37% | минимальный RMSE в текущем запуске |

В текущем эксперименте минимальный RMSE показала `LSTM` - 18.01. Далее идут `LinearRegression` с RMSE 19.36 и `AutoARIMA` с RMSE 23.92.

Этот результат относится только к выбранному тестовому отрезку. Один holdout-период недостаточен для окончательного выбора модели. Для более надежной оценки стоит дополнительно провести rolling backtesting или time-series cross-validation на нескольких временных окнах.

## 7. Интерпретация результатов

Результаты согласуются со структурой исходного ряда:

- `Naive` не учитывает ни тренд, ни сезонность и поэтому дает слабый ориентир
- `SeasonalNaive` заметно лучше благодаря повторению значений прошлого сезона
- `AutoARIMA` хорошо работает с трендом и автокорреляцией
- `LinearRegression` показывает сильный результат на лагах и календарных признаках
- `LSTM` дает минимальную ошибку в текущем запуске, но требует больше ресурсов и дополнительной проверки устойчивости

Если смотреть только на метрики текущего эксперимента, лучший RMSE у `LSTM`. Если учитывать простоту, скорость и воспроизводимость, `LinearRegression` и `AutoARIMA` остаются сильными кандидатами для дальнейшего развития проекта.

## 8. Базовый пайплайн

Повторно используемый код находится в `src/time_series_project`, а `src/ts_pipeline.py` сохраняет совместимость с существующими ноутбуками.

Базовый пайплайн выполняет следующие шаги:

1. загружает CSV
2. определяет колонку даты и колонку значений
3. очищает и сортирует временной ряд
4. определяет частоту и сезонный период
5. делит ряд на train и test без перемешивания
6. строит прогнозы Naive, SeasonalNaive и Drift
7. рассчитывает MAE, RMSE, MAPE и sMAPE
8. измеряет время основных этапов
9. сохраняет метрики, время выполнения и прогнозы в CSV

Результаты сохраняются в:

- `reports/final_pipeline_results.csv`
- `reports/pipeline_performance.csv`
- `reports/baseline_predictions.csv`

Итоговый ноутбук `notebook/06_final_pipeline.ipynb` используется как наглядная проверка того же общего процесса.

## 10. Вывод

В проекте выполнен полный учебный цикл работы с временными рядами: EDA, проверка стационарности, анализ аномалий, статистические модели, ML-модели, DL-модели и воспроизводимый базовый пайплайн.
На текущем тестовом отрезке минимальный RMSE показала `LSTM`. При этом размер ряда и один тестовый горизонт не позволяют считать результат окончательным выбором модели для эксплуатации.
Следующий логичный этап развития проекта - rolling backtesting на нескольких временных окнах и фиксация единого процесса выбора модели по качеству, скорости и устойчивости.
