# Model Card - LSTM для прогнозирования пассажиропотока

> Документ составлен по структуре **Google Model Cards for Model Reporting**. Описывает **реально исследованную конфигурацию LSTM**, а не развёрнутый промышленный сервис.

## 1. Сведения о модели (Model Details)

| Параметр | Описание |
| --- | --- |
| Название | LSTM - прогнозирование международного авиапассажиропотока |
| Проект | [project_neto_time_completion](https://github.com/AndreyBers/project_neto_time_completion) |
| Разработчик проекта | AndreyBers |
| Дата карточки | 19.10.2026 |
| Тип задачи | Прогнозирование одномерного временного ряда (регрессия) |
| Алгоритм | LSTM (Long Short-Term Memory), рекуррентная нейронная сеть |
| Реализация | `neuralforecast.models.LSTM` в составе библиотеки `neuralforecast`, PyTorch |
| Состояние | Исследовательский эксперимент / offline-оценка; модель не развёрнута как production-сервис |
| Исходный эксперимент | [`notebook/04_neuralforecast_dl_models.ipynb`](notebook/04_neuralforecast_dl_models.ipynb) |
| Результаты | [`reports/neuralforecast_comparison.csv`](reports/neuralforecast_comparison.csv) |

**Краткое описание.** Модель прогнозирует будущие месячные значения международного пассажиропотока на основе предыдущих наблюдений. LSTM обучается на последовательностях, чтобы учитывать зависимость будущих значений от истории ряда, включая тренд и сезонную динамику. В рамках текущего исследования она показала наименьшую RMSE среди сравнивавшихся моделей на одном контрольном отрезке.

**Важно о границах реализации:** повторно используемый CLI-пайплайн из `src/time_series_project/pipeline.py` выполняет только базовые прогнозы (`Naive`, `SeasonalNaive`, `Drift`). LSTM запускается **в исследовательском ноутбуке**, её прогноз и метрики не являются результатом штатного CLI. Сохранённые веса LSTM и промышленный API прогнозирования в документации проекта не заявлены.

## 2. Назначение и сценарии использования (Intended Use)

**Целевая задача:** на имеющихся исторических месячных значениях предсказать пассажиропоток на следующие **12 месяцев**, оценить ошибку прогноза и сравнить подходы к моделированию временных рядов.

**Предполагаемые пользователи:** ML-разработчик, аналитик временных рядов, исследователь, проверяющий результаты проекта.

**Корректное применение:**

- сравнительное исследование LSTM и базовых, статистических, классических ML- и DL-моделей;
- демонстрация подготовки временного ряда, обучения и оценки прогноза без временной утечки;
- получение экспериментального прогноза и выявление направлений улучшения модели;
- использование выводов как аналитической основы для *потенциального* планирования спроса - только после дополнительной проверки на современных данных.

**Применение вне области назначения:** автоматическое управление рейсами, тарифами, персоналом или бюджетом; прогнозирование современных пассажиропотоков без переобучения; использование для других временных рядов без самостоятельной проверки; принятие критичных решений без экспертного контроля.

## 3. Данные и признаки (Training Data / Evaluation Data)

**Датасет:** [`data/raw/international-airline-passengers.csv`](data/raw/international-airline-passengers.csv). Классический ряд *AirPassengers* - 144 ежемесячных наблюдения с января **1949** по декабрь **1960** года. В файле исходные колонки `Month` (месяц) и `Count` (значение). **Единица измерения - тысячи пассажиров**, что важно для интерпретации абсолютных ошибок.

| Набор | Период | Объём | Использование |
| --- | --- | ---: | --- |
| Train | Январь 1949 - декабрь 1959 | 132 месяца | Обучение LSTM |
| Test (holdout) | Январь - декабрь 1960 | 12 месяцев | Однократная оценка прогнозов |

Разбиение осуществляется **хронологически**, без перемешивания. Тестовый интервал не должен включаться в обучение или построение входной истории модели; в ноутбуке используется `split_series(..., test_size=12)`.

Перед обучением данные загружаются, даты приводятся к временному типу, значения - к числовому, выполняются упорядочивание и проверка ряда. Для `NeuralForecast` используется таблица:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `unique_id` | строка | Идентификатор ряда (`airline_passengers`) |
| `ds` | дата | Начало соответствующего месяца |
| `y` | число | Фактический пассажиропоток (тыс. человек) |

LSTM использует **36 прошлых месяцев** как размер входного окна (`input_size=36`) для прогноза на **12 будущих месяцев**. В отличие от классических моделей проекта (`MLForecast`), для описанного LSTM-эксперимента отдельно не формируются признаки `month`, `quarter` и лаги `[1, 2, 3, 6, 12]`: это параметры *другого* эксперимента с линейной регрессией и ансамблями.

## 4. Обучение и параметры

Конфигурация из [`04_neuralforecast_dl_models.ipynb`](notebook/04_neuralforecast_dl_models.ipynb):

```python
from neuralforecast import NeuralForecast
from neuralforecast.losses.pytorch import MAE
from neuralforecast.models import LSTM

model = LSTM(
    h=12,
    input_size=36,
    loss=MAE(),
    max_steps=100,
    random_seed=42,
)
nf = NeuralForecast(models=[model], freq="MS")
nf.fit(df=train_df)
predictions = nf.predict()
```

- `h=12` - горизонт прямого прогнозирования в 12 месяцев;
- `input_size=36` - размер входного окна в 36 ежемесячных наблюдений;
- `loss=MAE()` - функция потерь при обучении;
- `max_steps=100` - ограничение шагов обучения, выбранное для короткого исследовательского запуска;
- `random_seed=42` - фиксированное начальное зерно генераторов случайных чисел;
- `freq="MS"` - месячная частота с отметкой начала месяца.

В сохранённом эксперименте обучение выполнялось на **CPU**. Остальные параметры архитектуры и оптимизации используются согласно настройкам версии библиотеки в окружении эксперимента; они отдельно не зафиксированы в ноутбуке. Полной гарантии побитовой воспроизводимости между разными платформами это не даёт.

## 5. Входные и выходные данные

**Вход:** упорядоченная историческая последовательность `y` с месячными датами и идентификатором ряда; обученной модели для предсказания необходима доступная история по крайней мере в объёме её входного окна. Значения тестового года на вход при формировании прогноза не подаются.

**Выход:** таблица `unique_id`, `ds`, `LSTM` - по одной числовой оценке пассажиропотока (в тысячах пассажиров) на каждый из 12 будущих месяцев. Это **точечный прогноз**: интервалы неопределённости в текущем эксперименте не рассчитываются.

После раскрытия тестовых значений прогноз сопоставляется с фактом, рассчитываются метрики и сохраняется сравнительная таблица. Результат нужен прежде всего для **анализа качества и выбора направления дальнейшей разработки**, а не для автоматического исполнения бизнес-решения.

## 6. Метрики качества (Metrics)

Используются четыре метрики регрессии:

| Метрика | Смысл | Как интерпретировать |
| --- | --- | --- |
| **MAE** | Средняя абсолютная ошибка | В тысячах пассажиров; меньше - лучше |
| **RMSE** | Корень из средней квадратичной ошибки | Сильнее штрафует крупные промахи; основная метрика сравнения |
| **MAPE** | Средняя абсолютная процентная ошибка | Ошибка в процентах от факта; нестабильна при значениях около нуля |
| **sMAPE** | Симметризированная процентная ошибка | Дополнительная относительная метрика, тоже имеет ограничения около нуля |

В реализации `forecast_metrics` из [`src/time_series_project/metrics.py`](src/time_series_project/metrics.py) точки с нулевым фактическим значением исключаются из MAPE; для sMAPE исключаются пары, где и факт, и прогноз равны нулю. Все наблюдения данного тестового набора положительны.

## 7. Количественные результаты (Quantitative Analysis)

**Один фиксированный holdout: январь - декабрь 1960 года (12 наблюдений).** Ниже - результаты из сохранённых отчётов репозитория, округлённые до двух знаков.

| Модель | Группа | MAE, тыс. пассажиров | RMSE, тыс. пассажиров | MAPE | sMAPE |
| --- | --- | ---: | ---: | ---: | ---: |
| **LSTM** | DL | **16,03** | **18,01** | **3,37 %** | **3,37 %** |
| LinearRegression | ML | 17,18 | 19,36 | 3,56 % | 3,60 % |
| AutoARIMA | Статистическая | 18,52 | 23,92 | 4,18 % | 4,03 % |
| SeasonalNaive | Baseline | 47,83 | 50,71 | 9,99 % | 10,57 % |

На данном отрезке LSTM снизила RMSE примерно на **7 %** по сравнению с LinearRegression и на **64,5 %** по сравнению с SeasonalNaive. При этом **MAE = 16,03 означает среднюю абсолютную ошибку около 16 тысяч пассажиров**, а не 16 отдельных пассажиров.

Источники: [`neuralforecast_comparison.csv`](reports/neuralforecast_comparison.csv), [`mlforecast_comparison.csv`](reports/mlforecast_comparison.csv), [`statsforecast_comparison.csv`](reports/statsforecast_comparison.csv), [`final_pipeline_results.csv`](reports/final_pipeline_results.csv).

**Ограничение оценки:** результаты приведены для одного временного интервала и одного сохранённого запуска. Доверительные интервалы метрик, распределения ошибок по нескольким независимым окнам и проверка стабильности при смене случайного зерна не представлены. Утверждение «LSTM - лучшая модель в целом» на их основе было бы некорректным.

## 8. Факторы, влияющие на качество (Factors)

**Существенные факторы:** выраженность годовой сезонности, устойчивость тренда, изменение масштаба пассажиропотока, аномальные месяцы, длина доступной истории, размер горизонта, изменение внешних условий и особенности обучения нейросети.

**Проверенные факторы:** модель оценена на одном историческом месячном ряде с горизонтальным разделением по времени. Отдельные метрики для пиковых/низких месяцев, смены режима, других стран или современных периодов не приводятся.

Персональные или демографические признаки пассажиров в данных отсутствуют; анализ точности по таким группам неприменим.

## 9. Этические аспекты и потенциальные риски (Ethical Considerations)

- **Персональные данные:** используется агрегированный исторический временной ряд без индивидуальных сведений о пассажирах.
- **Риск неверной интерпретации:** единица измерения - тысячи пассажиров; ошибка в единицах может привести к неверным выводам о точности.
- **Риск неверных решений:** точечный прогноз без интервалов неопределённости и проверки на новых данных нельзя использовать как единственную основу для финансовых или операционных решений.
- **Смещение во времени:** данные 1949–1960 годов не отражают современные изменения отрасли, ограничений и структуры спроса.
- **Проверяемость:** приведены ссылки на исходный эксперимент и сохранённые метрики; повторный запуск и сравнение необходимы при изменении окружения.

## 10. Ограничения и рекомендации (Caveats and Recommendations)

1. Всего **144 наблюдения** - мало для уверенной оценки обобщающей способности нейросети.
2. Только **один год тестирования**; результатов rolling-origin / rolling-window backtesting пока нет.
3. Модель не учитывает внешние факторы: цены, экономические условия, праздники, изменения маршрутов и чрезвычайные события.
4. Обучение ограничено **100 шагами**; гиперпараметры не проходили полноценную настройку.
5. Текущая реализация выдаёт **точечные прогнозы**, без доверительных/предиктивных интервалов.
6. LSTM присутствует **в экспериментальном ноутбуке**, но пока не в рабочем CLI-пайплайне; интерфейса регулярного переобучения и мониторинга сдвига данных нет.

**Перед возможным практическим применением:** провести rolling backtesting на нескольких окнах, исследовать ошибки по месяцам, сравнить с простыми моделями на одинаковых условиях, проверить более современные релевантные данные, оценить устойчивость к выбросам, добавить интервалы прогноза, контроль дрейфа и регламент переобучения.
